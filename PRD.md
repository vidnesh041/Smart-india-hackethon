# PRD (Product Requirement Document)
## AI-Driven Hyper-Local Business Advisory & Financial Structuring Assistant
### Smart India Hackathon 2026 — Problem Statement ID: 26091

---

## 1. What to Build

Build a web application that acts as an **AI-powered personal financial advisor** for rural micro-entrepreneurs. The application collects a user's basic business and financial details (through a form or voice input), matches them to the correct government concessional loan scheme (e.g., Micro Finance Scheme, NSFDC tiers), calculates the exact loan structure (margin money, loan amount, interest, EMI), and generates a simple, personalized advisory explanation along with a basic business plan — all in plain, easy-to-understand language.

**Core Goal:** Replace the confusing, generic information currently offered by portals like Umang or Jan Samarth with a **personalized, calculation-backed, conversational advisor** that a rural entrepreneur can actually act on.

**Core Purpose:**
- Remove dependency on middlemen/agents for scheme guidance.
- Make government credit schemes accessible and understandable to low-literacy, rural users.
- Provide 100% accurate financial calculations (never AI-guessed numbers).

---

## 2. Targeted User

**Primary User:** Rural micro-entrepreneurs (e.g., dairy owners, small shopkeepers, tailors, artisans) who:
- Want to start or expand a small business using government-backed concessional credit.
- May have low digital/text literacy — voice-first interaction is essential.
- Speak regional languages (Hindi and other regional languages should be supported).
- Do not understand financial jargon (interest rate, margin money, EMI, moratorium).
- Have limited or no access to a financial advisor or CA.

**Secondary User (for demo/hackathon context):** SIH judges evaluating the completeness, usability, and real-world impact of the solution.

**Pain Points Being Solved:**
- No single source tells them *which* government scheme fits *their* specific business.
- No tool calculates their exact loan/margin-money split.
- No tool generates even a basic business plan for them.
- Middlemen exploit this information gap.

---

## 3. Features

### Must-Have (Core, for MVP/Hackathon Demo)
1. **User Input Collection** — Simple form: business type, investment amount, location, experience.
2. **Voice Input** — Microphone button using Web Speech API; converts speech to text; auto-fills the form.
3. **Scheme Matching Engine** — Rule-based logic (backed by a stored database of scheme rules) that matches user's business profile to the correct scheme/tier.
4. **Loan Calculator** — Deterministic Python logic (NOT AI) that computes:
   - Margin money (typically 10% of project cost)
   - Loan amount (remaining 90%)
   - Interest amount and EMI over the scheme's repayment period
5. **AI Advisory Text Generator** — Uses an LLM (OpenAI API) to turn the calculated numbers into a simple, human-readable explanation in the user's language.
6. **Basic Business Plan Generator** — Simple projected expense/income summary based on business type and investment amount.
7. **Result Display Page** — Clear, card-based UI showing scheme name, numbers, and advisory text.

### Nice-to-Have (If Time Permits)
- Nearby bank/agency suggestion (static data or Google Places-style lookup).
- Multi-language text output (Hindi/regional translation).
- Downloadable/shareable PDF of the advisory result.
- WhatsApp bot integration for outreach.

### Explicitly Out of Scope (for Hackathon MVP)
- Actual loan disbursement or bank integration.
- Real user KYC / real financial data handling (dummy/demo data only).
- Authentication beyond a simple demo login (not a priority for MVP).

---

## 4. Success Criteria (Definition of Done for Demo)

- A user can input details via voice OR form.
- The app returns a scheme recommendation with **accurate** numeric loan structuring.
- The app displays a plain-language advisory explanation generated by AI.
- The full flow (input → calculation → AI explanation → display) works end-to-end without manual intervention.

---

## 5. Constraints & Non-Negotiables

- **All numeric/financial calculations must be done in backend Python code — never by the AI model.** AI is only used for natural-language explanation generation.
- Must work with **demo/dummy data only** for the hackathon (no real user financial data).
- Must be voice-accessible (Web Speech API) since target users may be low-literacy.
- Must be buildable and demo-able within hackathon time constraints — prioritize MVP over polish.
